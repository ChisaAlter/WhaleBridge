# 媒体 URL 与 fake-IP：授权边界及实施依赖 · 2026-10-23

本轮范围仍固定在 Magpie [`e00fbdbbc74f9829027a78769cbeb265d6271fb4`](https://github.com/yetone/magpie/commit/e00fbdbbc74f9829027a78769cbeb265d6271fb4)。直接来源为 [`ea3dee96`](https://github.com/yetone/magpie/commit/ea3dee96a89cfb4710326342e840d58811eaa79a) 的媒体下载授权收口和 [`240f3eb4`](https://github.com/yetone/magpie/commit/240f3eb4c5faca86fed15b48ee984ec38c49860c) 的受约束 fake-IP 兼容；不引入上游新 web_fetch 工具或网关插件生命周期。

## 先决结论

这些改动可在现有内联网关中独立完成。完整依赖是：本机设置授权 → 备份恢复及同步边界 → 共享地址分类 → 按跳检查的下载客户端 → 调用者图片、供应商图片／视频和 MCP URL 兜底四个消费路径。只放开 `198.18.0.0/15` 会使字面地址和混合 DNS 答案绕过原保护；只去掉本机调用例外则会让本地服务失去可解释的显式授权入口。

## 授权由谁给出

| 来源或场景 | 本机下载的权限 |
| --- | --- |
| 调用者在本机、IPv6 loopback、浏览器或同机反向代理 | 不因来源位置增加权限；仍须私有网关密钥，媒体地址另行检查。 |
| 默认媒体 URL | 仅公共地址，DNS 全部答案通过后固定本次地址；每次重定向重新检查。 |
| 本机设置文件的 `fetchPrivate` | 用户明确列出的主机、主机和端口、IP 或 CIDR 可用于媒体下载。主机不带端口表示任意端口；需要收窄时应写 `host:port`。 |
| 普通页面设置请求 | 不能添加、移除或替换 `fetchPrivate`；省略此字段的正常保存也保留已有授权。初始页面 DTO 不返回本机清单。 |
| 导入备份／远端同步 | 恢复使用本机当前清单，外机清单不授予本机权限；只变更此字段不应产生设置同步差异。 |
| 供应商回答中的媒体 URL | 除公共地址与显式授权外，仅增加该供应商已配置协议端点的精确主机及端口；不会授予整个主机的其他端口、子域或重定向目标。 |
| 调用者提供的输入图 | 不继承供应商 own-host 例外；用户必须明确授权本机下载该地址。 |
| MCP 下载生成图片的 URL 兜底 | 使用同一受保护公共客户端与本机显式授权；不从回答 URL 猜测供应商或继承其端点权限。 |

`fetchPrivate` 是本机授权配置，不是 API 密钥。加密备份的数据结构可以序列化这个字段；“恢复不采纳”与“备份没有携带”是不同的保证。同步比较经 `KeepOwn` 清掉本机字段，恢复经 `KeepOwn` 放回本机值。当前设置读失败且没有可读的有效代际时不授予清单中的额外权限；供应商自己已配置端点的精确授权独立判断。

配置由启动器提供的组件数据目录中的设置文件读取，本轮不会改动已安装组件或用户真实清单。示例仅说明字段格式：

```json
{
  "fetchPrivate": ["nas.home:8080", "192.168.50.12", "192.168.60.0/24"]
}
```

## DNS、代理与 fake-IP

1. 私有、loopback、链路本地、元数据、CGNAT、组播、未指定、文档、保留及 IPv4 嵌入 IPv6 的非公共地址默认拒绝。主机授权或 IP/CIDR 例外由用户明确给出；未知或无效 DNS 答案不因此成为可连接地址。
2. 普通公共域名及已授权主机固定本次解析地址。TLS SNI 保留原主机；直连拨号再检查实际地址。普通代理收到固定地址，不能重新解析成另一地址。
3. Loon 的 `fd27:712::/96` AAAA 只有在同次答案含对应 IPv4 时才剔除，随后仍检查 IPv4。未配对 AAAA 和其他 ULA 地址不豁免。
4. fake-IP 兼容只适用于命名主机：剔除配对 Loon AAAA 后，所有答案都必须在 `198.18.0.0/15`。字面地址以及 fake 与真实地址混合的答案不获得自动例外。
5. 没有代理时按纯 TUN 路径固定并拨号本次 fake 地址，拨号保护不接受范围内其他地址。只有 loopback IP 或 `localhost` 的本机代理可以收到原名称；HTTP Host、CONNECT 和 SOCKS 目的地均须来自已检查的 URL。远端代理不能使用这个自动兼容例外。
6. 显式主机／IP 授权是用户另行给出的权限，与自动 fake-IP 兼容不同。重定向逐跳重新判断，不把一次成功检查升级为后续下载的授权。

fake-IP 模式中，名称最终指向哪里由用户的 DNS／TUN／本机代理决定，鲸桥看不到其后的真实目的地。如果解析器规则把名称送往内网，兼容路径也会跟随该规则；因此它依赖本机代理配置，不能描述为已证明最终地址一定在公网。

## 各下载出口的结果

- 输入图下载失败或内容不是图片：保留原编辑／生成错误路径，不把非图片正文当作图片传出。
- 已生成且付费的图片 URL 下载被拒或失败：仍把供应商 URL 返回给调用者，不静默丢弃生成结果。
- 供应商状态返回的视频 URL 下载被拒或失败：返回原 502 错误路径，不回传内部服务正文。
- MCP URL 兜底失败：告知生成结果仍在原 URL，不落盘下载失败的内容。
- 固定供应商 API 请求、用户明确配置的 MCP 服务、模型本身读取消息中的 URL 不在本机媒体下载授权链上；这些路径沿用各自配置和认证边界。

媒体下载请求不附带供应商 API 认证头、调用者密钥或 Cookie。供应商代理选择沿现有 `Via` 上下文，下载时间、大小、内容判断和 URL 回退语义保留。

## 共享规则与独立验证

`netguard.Public` 从网关原地址规则抽取。图标原判定较宽，接共享规则会收紧 0/8、240/4、IPv6 文档／Teredo、NAT64 私网等情况；旧图标把所有 6to4 拒绝，共享规则则按其中的 IPv4 分类。图标保留既有独立 fake-IP 兼容和 iconproxy 入口，不继承媒体的 `fetchPrivate` 或供应商 own-host 例外，因此不能把图标改动称为完全等价重构。

验收使用隔离设置、假 DNS、本地 HTTP／CONNECT／SOCKS 与 TUN 替身，检查：本机来源不授权；主机端口与 CIDR；所有 DNS 答案、重绑定、跨主机／端口重定向；代理路由与 Host；图片 URL 回退和视频拒绝；MCP 实际协议下载；普通设置保存、加密备份导入、本机撤销及两机同步。真实 Clash／Surge／Loon 和外部供应商不作为本轮自动测试的依赖。
